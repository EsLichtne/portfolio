# AGENTS.md

Статический сайт-портфолио: HTML, CSS, vanilla JS. Без сборки и зависимостей.
Исходный код открывают как часть портфолио — читаемость разметки важна наравне с результатом.

**Проект в работе.** Структура, блоки и раскладка ещё меняются. Правила ниже описывают, как себя вести, а не какой должна быть вёрстка. Если код разошёлся с этим файлом — скажи об этом, не подгоняй код под файл.

Визуальные решения — в `DESIGN.md`. Перед правками внешнего вида прочитай его. Поведение и ограничения работы агента — в этом файле.

## Где что лежит

```
/                  страницы верхнего уровня (главная; 404 — планируется),
                   плюс корневые документы вроде DESIGN.md и AGENTS.md
cases/             страницы кейсов, по файлу на кейс
css/               стили, четыре файла с разделением обязанностей:
                   tokens.css      только :root с переменными, без правил
                   reset.css       сброс браузерных умолчаний
                   typography.css  @font-face и классы шкалы
                   main.css        раскладка, блоки, состояния, медиазапрос
js/                скрипты
assets/fonts/      .woff2, подключаются локально
assets/images/     общие изображения и логотип
assets/images/cases/<кейс>/   изображения кейса, папка на кейс
en/                английская версия (планируется), зеркалит структуру корня
```

Правила:
- Файл кладётся по назначению, а не по удобству: переменная — в `tokens.css`, правило блока — в `main.css`. Переменная, объявленная в `main.css`, или правило блока в `reset.css` — ошибка.
- Изображение кейса живёт в папке своего кейса, а не в общей.
- Корень остаётся чистым: там только страницы верхнего уровня и файлы, которым положено быть в корне.
- Не создавать `en/`, 404 и другие отсутствующие страницы без явного запроса.

## Зависимости

- Только HTML, CSS, vanilla JS. Не добавлять фреймворки, npm, сборщики, препроцессоры, Tailwind, CDN-ссылки, иконочные библиотеки.
- Шрифты подключаются локальными файлами через `@font-face`. Ссылки на Google Fonts и шрифтовые CDN не добавлять, `@import` не использовать.
- Внешних запросов у сайта нет: шрифты, стили, скрипты и изображения — свои.
- Новая зависимость, новый CSS- или JS-файл — сначала спросить.

## Именование

- BEM: `block__element--modifier`.
- Текстовый узел с собственной ролью в блоке получает два класса: шкалу из `typography.css` и позиционный BEM. Пример: `class="text header__lang"`.
  Размер, вес и начертание задаёт только класс шкалы. BEM отвечает за положение и отступы.
  Исключение: однородный prose и meta без отдельной роли в блоке (абзацы внутри `case-prose`, ячейки meta) могут жить только на классе шкалы — `class="text"` / `class="heading"`. Не раскатывать BEM на каждый абзац ради правила.
- Состояния — префикс `is-`, проставляет JS.
- Имя описывает роль элемента, а не его вид: не `case__title-big`, а `case__title`.

## Значения

- Цвет и гарнитура — только через токен из `tokens.css`. Литерал цвета в CSS — ошибка, даже если совпадает со значением токена.
- Расстояния между крупными частями страницы — через токены ритма.
- Внутренние отступы компонентов — как в соседнем коде. Прежде чем взять новое значение, посмотри, чем набраны соседние блоки, и возьми оттуда.
- Один мобильный порог, как в `main.css`: десктоп от `1336px`, мобильный медиазапрос — `max-width: 1335px`. Новый брейкпоинт не вводить без запроса.
- `typography.css` — исключение: значения там литеральные, файл перенесён из Figma целиком, токенизировать не нужно.

## Структура

- Новый блок собирается по образцу существующего: открой ближайший похожий и повтори его устройство. Новых уровней обёрток не добавлять без необходимости.
- Состояния (`:hover`, `:focus-visible`, `:active`) описываются рядом со своим блоком, а не глобальными селекторами по тегу.
- Без инлайновых стилей, без `!important`, без id-селекторов — id только для якорей и хуков JS.
- Шапка, футер и `<head>` продублированы по страницам. Правишь одно — правь во всех, за один проход, и проверь относительные пути.

## JS

- Страница обязана читаться без JS. Контент скриптом не подставляется.
- Одна фича — один изолированный блок. Существующие не переписывать под общую абстракцию.
- Хуки JS — через `data`-атрибуты, не через классы оформления.
  Состояние по-прежнему вешается классом с префиксом `is-`.

## Контент

- Тексты кейсов не писать, не переписывать, не сокращать, не «улучшать».
- Не придумывать заголовки, подписи к изображениям, alt-тексты со смыслом, цифры и формулировки результатов.
- Текст не влезает в раскладку — сказать об этом, а не порезать.
- Не вычищать и не «нормализовать» `&nbsp;` и другую типографику в копирайте.
- Текст живёт только в HTML: без текстового содержимого в `content:` псевдоэлементов и без строк с копирайтом в JS — иначе английская версия станет дороже. Пустой `content: ""` для раскладки допустим.

## Доступность

- Один `h1` на страницу, иерархия заголовков без пропусков.
- `alt` у всех изображений; декоративные — `alt=""` плюс `aria-label` на родительской ссылке.
- Трогаешь интерактивный элемент — добавь видимый `:focus-visible` рядом с его блоком. Не раскатывать focus-стили на весь сайт без запроса.
- Анимации учитывают `prefers-reduced-motion`.
- `lang` на `<html>`, `aria-label` у каждого `<nav>`.

## Процесс

- Правка больше одного файла — сначала план списком, ждать подтверждения.
- Диффы маленькие. Не рефакторить попутно то, о чём не просили. Не переформатировать файл целиком ради одной строки.
- Наткнулся на странность — недоделку, заплатку, значение мимо системы — скажи о ней отдельно и продолжай свою задачу. Не чинить молча: часть таких мест сделана намеренно.
- При неопределённости — задать вопрос, а не угадать.
- Изменил поведение или стили так, что расходится с `AGENTS.md` или `DESIGN.md` — спроси, стоит ли обновить эти файлы. Не обновляй их молча и не оставляй расхождение незамеченным.

## Чеклист после правки

1. Литеральных цветов и гарнитур не добавилось.
2. Проверено на десктопной и мобильной ширине (порог `1335` / `1336`).
3. Консоль чистая.
4. С отключённым JS страница читается.
5. Трогал шапку, футер или `<head>` — синхронизировано во всех файлах, пути верны.
6. Трогал sticky/fixed — учтён отступ под хедер (`--header-height`).
